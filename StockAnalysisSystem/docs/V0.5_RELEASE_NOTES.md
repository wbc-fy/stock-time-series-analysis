# V0.5 发布说明：Flink 实时指标链路

发布日期：2026-09-30

## 主要变化

- 新增 Java 21/Flink DataStream 作业，消费 `stock.ods.daily.v1`。
- 按 `tsCode` 在 Flink managed keyed state 中维护最多 20 个唯一交易日。
- 输出 MA5/10/20、成交量 MA5/10 和量比，全部使用 `BigDecimal`、六位小数和 `HALF_UP`。
- 主输出写入 `stock.dws.daily-indicator.v1`；旧日期写入 `stock.late.daily.v1`；协议非法消息写入 `stock.flink.dead-letter.v1`。
- 三个 Kafka Sink 均使用 `EXACTLY_ONCE`，结果消费者必须使用 `read_committed`。
- 新增 Collector 历史重放命令 `replay-daily-events`，按 `trade_date ASC, ts_code ASC` 从 MySQL 分批预热状态；可用 `--ts-code` 参数化限定单股进行安全的真实对账，省略时保持全市场行为。
- Docker Compose 新增一个 JobManager、一个三 slot TaskManager 和持久化 checkpoint volume。
- 新增 valid、late、invalid 和 TaskManager restart/recovery 自动验收脚本。

## 固定技术栈

| 组件 | 版本 |
| --- | --- |
| Java | 21 |
| Apache Flink core/test-utils | 2.2.0 |
| Flink Kafka Connector | 5.0.0-2.2 |
| Flink Docker image | `flink:2.2.0-scala_2.12-java21` |
| Kafka Docker image | `apache/kafka:4.1.0` |

早期方案中的 Flink 2.3 已在提交 `6ab8e59` 中修正：当前没有与 Flink 2.3 匹配的已发布 Kafka Connector，不得混用 2.3 core 与 2.2 connector。

## 兼容性与数据边界

- `StockDailyEvent` V1 输入协议、Kafka key=`tsCode` 和 V0.4 Topic 不变。
- V0.4 的 Collector→MySQL、Java Consumer、Analysis App 和 Streamlit 不依赖 Flink。
- Flink 不读写 MySQL、ClickHouse、Redis、`stock_features` 或 `analysis_result`。
- 同一最新交易日会替换状态中的最后一点并再次输出；更旧交易日只进入 late Topic，不修改主状态。
- 指标不足窗口时为 `null`；`windowSize < 20` 时 `isWarmup=true`。

## 上线顺序

1. 在 `java-services` 执行 `mvn -q -pl flink-realtime-job -am package`。
2. 在项目根目录执行 `docker compose -f infrastructure\docker-compose.yml up -d`。
3. 执行 `powershell -ExecutionPolicy Bypass -File scripts\submit_v05_flink_job.ps1`，只提交一次。
4. 在 [Flink UI](http://localhost:8082) 确认作业 `RUNNING`，再重放至少 20 个实际交易日。
5. 使用 `read_committed` 消费结果并运行 `scripts\verify_v05_flink.py` 的 smoke scenarios。

详细命令见项目 [README](../README.md)，验收证据见 [V0.5 对账报告](V0.5_RECONCILIATION_REPORT.md)。

## 回滚

升级或替换 JAR 前先创建并记录 savepoint。回滚时取消 V0.5 Flink 作业，再执行 `docker compose -f infrastructure\docker-compose.yml stop flink-taskmanager flink-jobmanager`，将 Collector 切回 `COLLECTOR_OUTPUT_MODE=mysql`（或沿用既有 V0.4 输出策略）；不要停止 Kafka、V0.4 Java Consumer、MySQL 和 Analysis App，不要删除 Topic、checkpoint volume 或 savepoint。当前 Session Cluster 不配置 HA；JobManager 冷启动后需要从 retained checkpoint/savepoint 显式 resubmit，而非声称自动恢复。

## 已知限制

- Compose 是单 broker、单 JobManager、单 TaskManager、复制因子 1 的本地开发配置，不是生产高可用部署。
- keyed state 只保留最近 20 个唯一交易日，不负责历史任意区间修订。
- 2026-10-03 已补验隔离未提交事务故障/retained checkpoint 显式恢复，以及真实 MySQL `000001.SZ` 2026-04-29..2026-05-29 的20交易日 replay；六项指标逐日与既有 FeatureEngineer 对比共120项一致。具体资源、计数及边界值见对账报告；当前没有配置 JobManager HA，不能把手工 resubmit 称为自动恢复。
- 当前只允许一个名为 `stock-daily-indicator-v1` 的运行中作业；提交脚本会拒绝重复提交。
