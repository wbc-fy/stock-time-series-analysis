# V0.6 持久指标与真实行情页面

V0.6 将 Flink 日线指标持久化到 ClickHouse，由独立 Java Market API（8083）提供查询。MySQL 仍保存原始日线与股票资料；不迁移分析应用的特征或模型表。链路为 Collector → MySQL/Kafka → Flink → 事务 Kafka DWS → Market API Consumer → ClickHouse → 查询 API → Vue 分析概览。监控页仍读取 Java Consumer（8080）；分析概览为真实数据，其余八个页签禁用/展示演示占位，不宣称已有预测或回测功能。

## 安全启动顺序

从 `StockAnalysisSystem` 目录执行以下命令，每条命令为单个 PowerShell 物理行。先配置私有 `.env`（参照 `.env.example`），特别是非空 `DB_PASSWORD`、`CLICKHOUSE_PASSWORD`；勿打印或提交密钥。

已有 Kafka/Flink 集群时，只启动新增服务，不重建现有集群：

```powershell
D:/Python/python.exe -m dotenv -f .env run -- docker compose -f infrastructure/docker-compose.yml up -d --no-deps clickhouse
```

ClickHouse 25.8 使用独立持久卷 `clickhouse_data`，HTTP 8123 仅绑定回环地址。初始化 SQL 只在首次初始化运行；已有卷需人工确认并应用迁移，不能删卷强制初始化。现有 Flink 挂载可能仍指向历史 worktree，活动作业更换挂载需兼容 checkpoint 恢复，不能删除旧挂载目录或 checkpoint。冷启动、savepoint 与恢复操作见 [V0.5 运行指南](../README.md#flink-实时指标)及 [测试用例](V0.5_TEST_CASES.md)。禁止将 `docker compose down -v` 当作常规重启。

Java 不自动加载 dotenv。安装 Collector 已用的 PyMySQL、python-dotenv，并为 dotenv CLI 安装 Click（或 `python-dotenv[cli]`）。先设置 JDK 21 的 JAVA_HOME/PATH；停止自己正在运行的 Market API 后打包，Windows 正在运行的 JAR 会被锁定。不要停止 Kafka/Flink，也不要清理 group offsets 或 checkpoint：

```powershell
mvn -B -f java-services/pom.xml -pl market-api-service -am package
D:/Python/python.exe -m dotenv -f .env run -- java -jar java-services/market-api-service/target/market-api-service-0.3.0-SNAPSHOT.jar
```

若产物版本不同，以 `java-services/market-api-service/target` 的实际可执行 JAR 为准。私有环境由 CLI 继承，不输出密码。配置与精确消费者行为见 [Market API README](../java-services/market-api-service/README.md)。前端从 `frontend` 安装依赖并运行开发服务，见 [前端说明](../frontend/README.md)。

## 查询契约

| 请求 | 返回与边界 |
|---|---|
| `GET /api/analysis/stocks?limit=6000` | MySQL 股票资料数组，代码升序，limit 1..6000 |
| `GET /api/analysis/kline/000001.SZ?limit=260&start=2026-04-29&end=2026-05-29` | `{ts_code,bars}`，MySQL 原始 OHLCV、pre_close/change/pct_chg/amount |
| `GET /api/analysis/indicators/000001.SZ?limit=260&start=2026-04-29&end=2026-05-29` | `{ts_code,indicators}`，ClickHouse FINAL 逻辑去重后的指标 |

Series limit 1..2000，默认 260；日期为可选 ISO 日期，含首尾，start ≤ end；先选最近 limit 行，再按日期升序返回。代码必须为六位数字加 `.SH/.SZ/.BJ`。非法参数 400，未知股票 404，已知股票空序列 200 空数组，依赖失败 503 且错误脱敏。Kline 与股票池只依赖 MySQL；指标先确认 MySQL 股票存在，再查 ClickHouse。数值为 JSON number；日期为 ISO，预热指标为 null。MA5/10/20、vol_ma5/10、volume_ratio 按 Decimal 六位 HALF_UP；量比使用已舍入的 vol_ma5，均量为零时 null。

前端 MA 按交易日期关联 Kline，不按数组位置拼接；数据不足或指标 503 时保留真实 Kline，MA 保持 null，不回填模拟数据。股票变化/卸载取消请求并隔离迟到响应。

## 去重、失败与恢复边界

消费者 `read_committed`；只有 ClickHouse 插入返回完整成功响应（`wait_end_of_query=1`）后才提交 offset。至少一次插入可能产生物理重复；ReplacingMergeTree 以 Kafka offset 为版本，`FINAL` 对 `(ts_code,trade_date)` 即时逻辑去重。这不是跨 MySQL/Kafka/Flink/ClickHouse 的端到端 exactly-once。

当前输出 topic、股票 Key 分区规则及三分区数量固定。offset 只在同一 topic/partition 内可排序；重建 topic、重置 offset 或改变分区规则不能继续复用原表。需要协调新表、新消费组、重放、查询切换；不是日常恢复步骤。对未改变的 topic 使用新 group 可安全逻辑重放。

插入失败、坏消息或协议不匹配重试三次（1 秒间隔）后停止受影响消费者，不提交毒消息，不跳过至 DLT。健康检查 DOWN/503。人工查看脱敏日志及失败 topic/partition/offset，修复依赖或事件问题后有意识重启；先确认根因，不能自动清空 offset 或删表规避问题。Kafka 事务控制 marker 可造成 offset lag 1，不等于一条业务数据积压。

## 可复现只读对账

脚本仅执行参数化 SELECT 和 HTTP GET，不自动启动服务、重放、写库、提交 Kafka offset 或复位状态。可使用只读 MySQL 用户。默认最近一年，限定一只股票、最多 2000 日范围和 2000 行；HTTP/数据库 timeout 默认 10 秒、上限 30 秒。依赖失败、健康不为 UP、重复/无序日期或字段不一致均非零退出，异常不泄露连接参数。

普通模式读取查询前 19 条 MySQL 日线，仅对 API `window_size=20` 且源码上下文充足的日期检查六项指标，要求至少一项完整窗口；报告 checked 与 unchecked 日期，未检查预热指标不视为匹配。若确定首日开始于空 Flink state，才可显式使用 `--fresh-window`，它验证 `window_size=min(index+1,20)`、预热标记与 null；此参数不修改或创建 state。

```powershell
D:/Python/python.exe scripts/verify_v06_market_api.py --ts-code 000001.SZ --start 2026-04-29 --end 2026-05-29 --fresh-window
D:/Python/python.exe -m pytest --confcutdir=scripts/tests --rootdir=scripts/tests scripts/tests/test_verify_v06_market_api.py -q
```

本次真实历史验收：MySQL `000001.SZ` 的 2026-04-29..2026-05-29 共 20 个交易日 → Kafka read_committed 20 条 → ClickHouse API 20 条，120 项 Decimal 指标一致，末日 MA20=11.022；不是 Tushare 实时行情证明。只重放末日后物理 21/逻辑 20，后台合并后物理 20。仅停止 ClickHouse 的故障验收观察到 API 503、health DOWN，failed record offset 111 未提交（CURRENT 110/END 113）；恢复 ClickHouse 并重启自己的 API 后 CURRENT 112/END 113、health UP，120 项仍一致。

浏览器验收：5272 股票池、真实 260 条 Kline（末日 2026-08-17）、20 日期 MA 对齐，非空 MA5/10/20 为 16/11/1；已知空指标股票和模拟 503 均不生成假 MA。390px 无横向溢出，页面错误 0。验收记录描述的是这些历史数据和运行实例，不承诺实时更新、性能或预测收益。
