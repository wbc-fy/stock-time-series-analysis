# V0.7 单股真实 XGBoost 预测

V0.7 在 V0.6 真实行情概览旁接入预测标签页。数据从 MySQL 读取，训练及发布只能由显式离线命令执行；Python 只读 API（8084）和浏览器 GET 不训练、不发布、不自动建表。旧 `main.py`、LightGBM/Transformer、模型登记及 Parquet 缓存保持原路径和行为。

## 口径与限制

目标契约为 `next_trading_day_close_return`，`horizon=1`，公式 `close[t+1] / close[t] - 1`。API 保存小数收益率，例如 `0.01` 表示 `1%`，页面仅转换一次。RMSE/MAE 在 API 同为小数收益率，页面是百分点；R² 无单位、未定义时为 null，不是概率。零收益基线在同一完整测试序列上计算，不承诺模型优于基线，也不构成投资建议。

读取的是原始未复权收盘价，除权、除息和公司行动可能造成跳变；不是分红复权或经济总收益。`daily_basic` 可能被供应商追溯修订，不能据此保证历史时点可获得性（point-in-time）。训练和加载推理现在必须使用显式可信本地交易日历，在计算任何特征之前检查完整源日期逐条等于覆盖范围内全部开市日；缺口、非开市日或不完整覆盖均失败，不按工作日回退、填补或删除缺口行。

初次本地对账使用 `000001.SZ`，1066 条 MySQL 历史记录，范围 `2022-01-04..2026-08-17`，213 条冻结测试记录。源记录存在 `2026-05-29→2026-08-14` 的 77 个日历日间隔，因此这次对账只证明“下一条已存观测”的标签及指标一致，**不证明真实下一交易日 horizon=1**。系统日期为 2026-10-03 不会自动让模型或数据库截止日更新。补齐行情后须另行显式训练、发布及重新验收，不能复用旧模型评估冒充新验收。

用户随后授权补齐 `000001.SZ`，原有 1066 条保留，新增 84 条日线及 84 条每日指标，两表各有 1150 条记录，最新权威开市日为 `2026-09-30`。新模型已完成真实训练、加载推理、发布和独立验收；下列复现命令仍使用新模型 ID 占位符，需替换为自己训练的输出。原始旧模型 `v07_ef4385877b634871b56afd8db6d8921e` 无连续性证据，不再作为有效 V0.7 结果列出，直接查询返回脱敏 503；原文件和数据库行保留，不修改或删除。

## 配置与权限

使用已安装应用依赖，数据库参数由私有 `.env` 或环境变量 `DB_HOST/DB_PORT/DB_USER/DB_PASSWORD/DB_NAME` 提供。应用优先读取自身 `.env`，否则读取 `StockAnalysisSystem/.env`。不要提交、输出或把密码放入浏览器配置和命令行。以下示例均在仓库根目录的 PowerShell 中执行，每条命令单行；安装位置不同可替换 Python 路径。

数据库结构由管理员预先准备，本功能不运行 DDL 或 `create_all`。离线训练/推理发布账号只需源表 SELECT 和 `analysis_result` INSERT；API 账号仅需 `stock_basic`、`analysis_result` SELECT；对账账号仅需 `stock_daily` SELECT。不同进程用不同环境配置/账号启动，切勿因示例统一变量名就给 API 或对账器写权限。查询均有参数绑定、条数和连接/读取超时。

## 显式训练与加载模型推理

训练必须传带后缀股票代码、ISO 起止日期和 `--calendar`。日历是可信采集器导出的本地 JSON：`source="tushare.trade_cal"`、`exchange="SSE"`、ISO `start/end`、严格升序唯一 ISO `open_dates`。SH/SZ 可用 SSE，BJ 必须匹配 BSE，不能静默共用 SSE。文件不超过 256 KiB，覆盖不超过 10000 个日历日、最多 7500 个开市日，且覆盖整个源范围；重复 JSON 键拒绝。文件来源由操作者保证，来源字符串不是数字签名。历史上限 2500 行、最少 300 条有效历史，非法 OHLC、重复日期及不足历史明确失败；缺失可选估值可使用 XGBoost 原生 NaN。CPU、随机种子 42、有界参数；固定 `v07_fixed_1` 特征顺序不含未来标签。约 60/20/20 时间切分；训练标签结束日不进入验证区间，验证标签结束日不进入测试区间。已见边界包含训练和验证，测试不能用于拟合、调参或早停。

若还没有可信日历，可在现有 `python-collector` 目录及其私有环境中显式导出 SSE 日历（只调用既有采集器，不写数据库；不是 API GET 的自动任务）。下例检查覆盖每个日历日后写入已忽略的模型目录；修改范围需同步训练范围，不能用数据库已观察日期伪造权威日历：

```powershell
Set-Location F:/java-stock-analysis/stock-time-series-analysis/StockAnalysisSystem/python-services/python-collector
D:/Python/python.exe -c "import json,pandas as pd; from pathlib import Path; from app.collectors.tushare_collector import TushareCollector; start='2022-01-04'; end='2026-10-03'; df=TushareCollector().collect_trade_calendar(start,end); days=pd.to_datetime(df.cal_date,format='%Y%m%d').dt.strftime('%Y-%m-%d'); assert sorted(days.tolist())==pd.date_range(start,end).strftime('%Y-%m-%d').tolist(); assert df.is_open.isin([0,1]).all(); payload=dict(source='tushare.trade_cal',exchange='SSE',start=start,end=end,open_dates=sorted(days[df.is_open.eq(1)].tolist())); target=Path('../stock-analysis-app/models/v07/exchange-calendar.json'); target.parent.mkdir(parents=True,exist_ok=True); target.write_text(json.dumps(payload),encoding='utf-8')"
```

源行情或日历不足属于业务不可用，应补齐并重新显式训练；不能为了显示结果绕过校验。导出的私人日历不得提交。

在单独终端设置应用工作目录：

```powershell
Set-Location F:/java-stock-analysis/stock-time-series-analysis/StockAnalysisSystem/python-services/stock-analysis-app
D:/Python/python.exe -m scripts.forecast train --stock 000001.SZ --start 2022-01-04 --end 2026-09-30 --calendar models/v07/exchange-calendar.json
```

将下面 `<new_model_id>` 替换为新训练命令输出的 `model_id`；推理命令加载既有冻结模型，**不会重新训练**，但会向结果表新增一条发布记录：

```powershell
D:/Python/python.exe -m scripts.forecast predict --stock 000001.SZ --start 2022-01-04 --end 2026-09-30 --calendar models/v07/exchange-calendar.json --model '<new_model_id>'
```

测试与 latest 使用同一冻结模型，不在评估后重训。latest 来自真正最后一条行情且必须晚于模型已见边界，不需要真实 y；`actual_return=null`、`target_date=null`，页面标为“下一交易日”。它是截至数据截止日的历史预测，不是今天、实时或未来五天预测。`source_continuity` 冻结日历来源/覆盖、完整源日期序列及 SHA-256 日期摘要/计数，每个测试标签必须指向相邻已证明开市日。后续推理要求相同起始日和原日期前缀，只更新 latest/cutoff 及独立 `inference_continuity`，不改变冻结源证据、测试、指标、原始训练摘要和已见边界。

模型以 XGBoost 原生 JSON 与元信息存入受控 `models/v07/{model_id}`，不加载外部 pickle、不接受用户上传或请求文件路径。须信任本地模型存储并限制写权限。先原子完成模型文件，再事务性追加完整结果；失败不暴露半成品，旧记录不删除。重新训练生成新的不可变 ID，加载推理可产生同一 ID 的多个发布记录，`publication_id` 区分这些发布。模型输出被 Git 忽略；勿提交模型、`.env`、构建目录或依赖。

既有 MySQL `analysis_result.result` 为 TEXT，最多 65535 字节。发布使用无损紧凑 JSON，并在执行 SQL 前检查实际 UTF-8 编码长度；超过此容量会明确失败，不自动改表、截断或抽样证据/测试序列。300..2500 条历史是计算输入边界，不代表所有历史长度都能在既有 TEXT 中发布。存储失败可能留下已保存但未发布的模型文件，列表不会显示它；保留该文件和旧数据库行，不将其当作发布成功。本次曾因默认空格使完整结果达到 68728 字节而发布失败；无损紧凑结果为 64328 字节，修复后重新训练的新版本已成功发布并完成上述验收。

## 只读 API 与页面

在应用目录，用只读数据库账号启动：

```powershell
D:/Python/python.exe -m uvicorn api.forecast:app --host 127.0.0.1 --port 8084
```

在另一终端只读查询，完整对账要 `limit=500`（默认仅尾部 60 行，不能拿局部序列验算全测试指标）：

```powershell
Invoke-RestMethod 'http://127.0.0.1:8084/api/analysis/models?ts_code=000001.SZ'
Invoke-RestMethod 'http://127.0.0.1:8084/api/analysis/prediction/000001.SZ?model=<new_model_id>&limit=500'
Invoke-RestMethod 'http://127.0.0.1:8084/api/analysis/models/<new_model_id>/importance?top=15'
Invoke-RestMethod 'http://127.0.0.1:8084/api/analysis/results/000001.SZ'
```

`/models` 返回元信息数组，默认 20、最多 100；`/prediction` 返回 `{metadata,test_series,latest}`，序列最多 500；元信息有意不含重要性，重要性走专门端点（gain，top 1..100）。`/results` 是发布摘要数组，不是旧分析 JSON。非法输入 400、未知或跨股票模型 404、依赖故障脱敏 503，已知股票无模型是 200 空数组；无结果提示离线准备，不回退模拟数据。没有网页训练 POST。

回到仓库根目录启动前端：

```powershell
Set-Location F:/java-stock-analysis/stock-time-series-analysis/StockAnalysisSystem/frontend
npm.cmd run dev -- --host 127.0.0.1
```

选择“接入现有 API”，分析页可用真实概览及预测；其他未接入标签仍禁用，演示模式原功能保留。预测展示模型/切分/截止日、测试曲线、零基线和独立未知实际值卡片，不画概率、混淆矩阵或虚构未来价格。切换股票/模型会取消请求并拒绝过期响应。真实错误不触发演示回退。默认 `PREDICTION_API_TARGET=http://127.0.0.1:8084` 只代理明确预测路径，行情仍去 8083，监控仍去 8080；生产需配置同源反向代理，不应把整个 `/api/analysis` 指向 Python，也不能把数据库凭据放入 Vite。

## 独立只读对账

在仓库根目录运行（仅 SELECT、HTTP GET、读取受控元信息，不加载模型，不训练、不发布、不写缓存）：

```powershell
D:/Python/python.exe StockAnalysisSystem/scripts/verify_v07_prediction.py --stock 000001.SZ --model '<new_model_id>' --start 2022-01-04 --end 2026-09-30 --calendar StockAnalysisSystem/python-services/stock-analysis-app/models/v07/exchange-calendar.json --api-base http://127.0.0.1:8084
```

退出 0 表示明确范围的源观测与可信本地日历连续性对账 PASS。对账器不导入生产连续性或训练模块，独立检查冻结源证据和当前推理证据、完整日期前缀及相邻开市日标签；逐条用独立 Decimal 收盘比值验算实际收益，独立计算完整测试 RMSE/MAE/R² 和零基线；检查模型/股票绑定、严格日期顺序、切分与原始已见边界、最新未知实际值及冻结元信息一致性。JSON 数值容差为 `abs 1e-10 + rel 1e-8 × abs(expected)`，单位为小数收益率；不允许 NaN/Infinity、重复 JSON 键或不完整尾部样本静默跳过。

输出当前与冻结源记录数/起止日、checked/test 数、原始已见边界及超过 7 个日历日的合法观测间隔。`exchange_calendar_completeness_verified=true` 仅指给定可信日历和明确源范围；仍需信任日历文件来源，不能证明供应商真实性。`training_label_provenance_verified=false`：没有独立重建历史拟合选择或训练特征/标签；也不能证明估值未被追溯修订。PASS 不代表模型获利、复权经济收益或投资保证。失败退出 1 并脱敏，不打印数据库错误/密码。无需重放 Kafka、清空 MySQL、删除缓存、重建集群或检查点。
